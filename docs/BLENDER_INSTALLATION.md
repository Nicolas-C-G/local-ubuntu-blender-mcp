# Blender and Custom Add-on Installation

This project does not use Blender's official Lab MCP add-on. It installs a custom add-on that exposes only a small allowlist of operations over a token-authenticated loopback bridge.

## Supported deployment baseline

The source advertises Blender 4.2 compatibility through `bl_info`. The initial deployment-validation baseline is Blender 5.1 or newer. Do not describe a Blender version as supported until the acceptance checklist and real-Blender integration test pass on that version.

## Install Blender

Prefer the official Linux archive from Blender rather than assuming the Ubuntu repository contains the required version.

1. Download the Linux archive from <https://www.blender.org/download/> inside the VM.
2. Verify the download came from an official Blender domain.
3. Extract it to a versioned directory under `/opt`.

Example, after adjusting the filename and directory to the downloaded version:

```bash
cd "$HOME/Downloads"
tar -tf blender-*-linux-x64.tar.xz | head
sudo mkdir -p /opt/blender
sudo tar -xJf blender-*-linux-x64.tar.xz --strip-components=1 -C /opt/blender
sudo ln -sfn /opt/blender/blender /usr/local/bin/blender
blender --version
```

Inspect the archive before extracting it. The wildcard must identify exactly one intended Blender archive.

## Download the project source

The add-on files are part of this repository; they are not included in the
Blender archive. On a clean VM, install the required command-line tools and
clone the branch being tested before packaging the add-on:

```bash
sudo apt update
sudo apt install -y git zip unzip

mkdir -p "$HOME/apps"
cd "$HOME/apps"
git clone --branch feature/blender-mcp-mvp --single-branch \
  https://github.com/Nicolas-C-G/local-ubuntu-blender-mcp.git

cd "$HOME/apps/local-ubuntu-blender-mcp"
git branch --show-current
```

The last command must print `feature/blender-mcp-mvp`. If the repository is
already cloned, do not clone it again. Instead, enter the existing repository,
fetch the latest changes, and verify the branch before continuing:

```bash
cd "$HOME/apps/local-ubuntu-blender-mcp"
git fetch origin
git switch feature/blender-mcp-mvp
git pull --ff-only
git branch --show-current
```

## Package the custom add-on

Use the explicit repository path so this step does not depend on the terminal's
previous working directory:

```bash
rm -f /tmp/blender_mcp_bridge.zip

cd "$HOME/apps/local-ubuntu-blender-mcp/blender_addon"
test -f blender_mcp_bridge/__init__.py
zip -r /tmp/blender_mcp_bridge.zip blender_mcp_bridge -x '*/__pycache__/*' '*.pyc'
unzip -l /tmp/blender_mcp_bridge.zip

cd "$HOME/apps/local-ubuntu-blender-mcp"
```

The archive root must contain `blender_mcp_bridge/`, and that directory must contain `__init__.py`.

## Create the protected bridge environment

The add-on refuses to enable unless the Blender process has a
`BLENDER_BRIDGE_TOKEN` containing at least 32 characters. Create the protected
environment file **before** installing or enabling the add-on:

```bash
mkdir -p "$HOME/.config/blender-mcp"
chmod 700 "$HOME/.config/blender-mcp"

environment_file="$HOME/.config/blender-mcp/env"
umask 077
touch "$environment_file"
chmod 600 "$environment_file"

if ! grep -q '^BLENDER_BRIDGE_TOKEN=' "$environment_file"; then
  bridge_token="$(python3 -c 'import secrets; print(secrets.token_urlsafe(48))')"
  printf 'BLENDER_BRIDGE_TOKEN=%s\n' "$bridge_token" >> "$environment_file"
  unset bridge_token
fi

if ! grep -q '^BLENDER_BRIDGE_PORT=' "$environment_file"; then
  printf 'BLENDER_BRIDGE_PORT=8765\n' >> "$environment_file"
fi
```

Validate the token without printing the secret:

```bash
(
  set -a
  # shellcheck disable=SC1090
  source "$HOME/.config/blender-mcp/env"
  set +a

  if [[ -z "${BLENDER_BRIDGE_TOKEN:-}" || ${#BLENDER_BRIDGE_TOKEN} -lt 32 ]]; then
    echo "BLENDER_BRIDGE_TOKEN is missing or shorter than 32 characters" >&2
    exit 1
  fi

  echo "Bridge token is configured"
)
```

If validation fails because the file already contained an invalid value, edit
it with `nano "$HOME/.config/blender-mcp/env"`, replace that value with a new
secret generated by `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'`,
and run the validation again. Never commit, publish, or share the token. Keep
this token when adding the remaining MCP and Auth0 settings later in the
deployment procedure.

## Create the protected Blender launcher

The desktop application normally does not inherit variables from a terminal or systemd service. Use one protected environment file for both Blender and the MCP process.

```bash
mkdir -p "$HOME/.local/bin"
nano "$HOME/.local/bin/blender-mcp-session"
```

Paste:

```bash
#!/usr/bin/env bash
set -euo pipefail
environment_file="$HOME/.config/blender-mcp/env"
if [[ ! -r "$environment_file" ]]; then
  echo "Missing protected environment file: $environment_file" >&2
  exit 1
fi
set -a
# shellcheck disable=SC1090
source "$environment_file"
set +a
exec /usr/local/bin/blender "$@"
```

Then:

```bash
chmod 700 "$HOME/.local/bin/blender-mcp-session"
```

Make sure `$HOME/.local/bin` is in the user's `PATH`, or invoke the wrapper with its absolute path.

## Launch Blender through the protected launcher

Close every Blender window that was opened from the desktop menu or with the
plain `blender` command. Environment variables are read when the process
starts, so an already-running Blender instance cannot receive the token.

Launch Blender with:

```bash
"$HOME/.local/bin/blender-mcp-session"
```

Keep this Blender process open for the next step. Use the protected launcher
every time Blender needs to run with the MCP bridge.

## Install and enable the add-on

The exact menu wording varies slightly by Blender release:

1. In the Blender instance opened through the protected launcher, open **Edit → Preferences**.
2. Open **Add-ons** or **Extensions**.
3. Choose **Install from Disk**.
4. Select `/tmp/blender_mcp_bridge.zip`.
5. Enable **Blender MCP Bridge** if Blender did not enable it automatically.

Blender may try to register and enable the add-on immediately after **Install
from Disk**. This is why the bridge environment and protected launcher must be
configured first.

### Recover from a missing-token installation error

If Blender reports `Set BLENDER_BRIDGE_TOKEN to a secret containing at least
32 characters before enabling Blender MCP Bridge`, the ZIP was found but the
Blender process did not receive a valid token:

1. Dismiss the error and leave the add-on disabled.
2. Close Blender completely.
3. Create and validate the protected bridge environment as described above.
4. Relaunch Blender with `"$HOME/.local/bin/blender-mcp-session"`.
5. Return to Preferences and enable **Blender MCP Bridge**. Reinstall the ZIP only if the add-on is not listed.

## Verify the bridge

After the add-on is installed and enabled:

```bash
ss -ltnp | grep ':8765'
```

The address must be `127.0.0.1:8765`.

Verify that an unauthenticated command is rejected:

```bash
curl -sS -o /tmp/bridge-response.json -w '%{http_code}\n' \
  -H 'Content-Type: application/json' \
  --data '{"action":"health","arguments":{}}' \
  http://127.0.0.1:8765/command
cat /tmp/bridge-response.json
```

Expected result: HTTP `401`.

## Update the add-on

1. Keep mutations disabled.
2. Pull the reviewed repository update.
3. Recreate the ZIP.
4. Disable the old add-on.
5. Install the new ZIP and re-enable it.
6. Restart Blender through the protected launcher.
7. Repeat the local bridge and read-only acceptance tests.

## Remove the add-on

Disable and remove **Blender MCP Bridge** from Blender Preferences. Close Blender and verify nothing listens on `8765`:

```bash
ss -ltn | grep ':8765' || echo 'Bridge is not listening'
```
